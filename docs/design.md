# Telldes 設計書

README や実装からは読み取れない、意図と決めたことだけを書く。

## 目的

Figma で作った LP / HP のデザインを、Claude Code（CC）がカンプと同じ見た目のコードにできるようにする。カンプの画像だけを渡すと、背景と中身の区別、色・大きさ・間隔の値、見出しのレベル、どこが伸びてどこが固定か、動きを CC が推測し、外れる。

出力の正確さを何より優先する。出力が不正確なら、CC のコードもそのまま不正確になる。

## 前提

- デザイナーは1人。作るのは LP / HP
- Figma は無償版で使う。有料の機能には頼らない。組織内だけに配るプラグインは有料なので、Figma Community に公開する
- デザイナーに新しい作法を覚えさせない。Figma 公式のベストプラクティスを土台にし、telldes 独自の約束は公式のやり方で表せないことだけに限る。独自の約束は増えるほど守られない

## 決めたこと

### ファイルにある情報を書き出し、推測しない

ベストプラクティスどおりに作ったファイル（Auto Layout、変数、スタイル、コンポーネント）には、コードに要る情報がそろっている。telldes はそれを書き出すだけで、値から意図を推測しない。推測は外れても誰も気づかない。

Figma のデータに無いことは、プラグインで補足として受ける（次の節）。それでも無いものは「無い」と書いて渡す。CSS で同じに描けないもの（特殊なグラデーション、破線など）は Figma に描かせた画像で渡し、それもできなければ「含まれなかったもの」として伝える。近い見た目を CC に作らせない。

レスポンシブもこの考えで分ける。出力する Web ページ（HP なら top・about など）の幅ごとの見た目は別のフレームが持ち、どのフレームが同じ Web ページか、どの幅からそのフレームを使うか、コンテンツ幅は、デザイナーが Export 設定で宣言する。1440px のフレームの左右 340px の余白が、ただの余白なのかコンテンツ幅を作るものなのかは、描かれた幅では同じ見た目になり、データからは決められないから。どのフレームが組になるかもデータには無い。フレーム名から推し量ると telldes だけの約束になり、打ち間違いにも気づけない。

出力の形は次の4つを守る。

- 同じ種類のものは同じ形で出す
- 同じ事実を2か所に書かない
- 落としたものは、落としたと書く
- 指定されていないことは出さない

### デザインの判断はデザイナー、実装の判断は CC の利用者に聞く

デザインの判断はプラグインが Figma の上でデザイナーから受け、実装の判断（フォントの読み込み方、置き場所など）は CC が利用者に確認する。デザイナーは Figma を開いている今が一番答えやすく、zip を受け取る人がデザイナーとは限らない。

telldes は LLM を持たず、質問をその場で作れない。そこで、デザインするなら決めないといけないことを前もって洗い出し、決まった入力欄として用意する（Export 設定）。欄にするのは、CC が値としてそのまま使うもの（切り替える幅、ダーク対応の有無、Web ページの題名など）だけ。自由に書かせると書き方がぶれて機械的に読めないから。それ以外は文章で受ける。すべての Web ページに効くことは共通ルールに、個々のレイヤーのことは note に書く。Figma 標準の注釈は無償版で使えないので、note はプラグインで受ける。

### 判断は Figma に触らない部分に集める

Figma から読む部分は、読んだものを JSON にできるデータにまとめ、言われたとおりに書き込むだけで、判断しない。出力の中身・Review・テーマの付け替えの判断は、そのデータだけを受ける部分に集める。Figma なしで動かせ、テストで確かめられるのはこの部分だけだから。

Review と Export の出力は、一度読んだ同じデータから作る。別々に読むと、Review したものと渡したものがずれうる。

### Review は出力が壊れるときだけ止める

error にするのは、直さないと出力が壊れるもの、つまりデザイナーが選んだやり方との食い違いだけ。「変数を使え」は error にしない。ダーク対応を ON にしたファイルでだけ、変数につないでいない色を error にする（そこだけ Dark に付け替わらない）。指定し忘れたと機械的に分かるもの（トークンと同じ値なのにつないでいない、など）は、止めずに知らせる。同じ原因の違反は1行にまとめる（同じ色が30か所なら1行）。

ライトだけのファイルで値が変数になっていないことは、どこにも報告しない。値は `spec.json` に載り、CC は正しく作れる。並べると LP 1枚で数十〜数百行になり、本当に落としたものが埋もれるうえ、「変数を使え」と促すことにもなる。

Review が見るのは、Export が書き出すのと同じ範囲だけ。渡さないものを直さないと渡せない、という状態を作らない。範囲は同じ判定を共有し、Review と zip の対象がずれないようにする。Review はプラグインを開いたときと Export の実行前に自動で走る。error の件数を常に見せるには、開いた直後から値が要るから。

### ダークモードはフレームを複製せず、変数を付け替える

無償版では1つのコレクションに複数のモードを作れないが、コレクションの数には制限が無い。そこで変数を Light・Dark・Base（テーマで変わらないもの）の3つのコレクションに分け、ページ全体の変数のつながりを Light と Dark の間で付け替える。フレームを複製すると、同じページが別ページとして CC に渡り、Light の変更が Dark に伝わらない。

代償として、ファイルが「今どちらのテーマか」という状態を持つ。Export の途中で失敗しても必ず Light に戻し、それでも Dark で残った場合は、次に開いたときに戻すよう促す。また、キャンバスで Light と Dark を並べて比べられない。比べるのは Export した画像で行う。

### 変数とスタイルの一式は Setup が作る

無償版ではファイルをまたいで変数を共有できず、手で作らせると、使える欄の絞り込みや CSS 変数名の設定を漏らす。何度押しても増えないように、あるべき一式と今あるものの差だけを作る。Setup を使わずに作ったファイルも、そのまま読めて正しく出る。

### プラグインの画面はオブジェクト指向（OOUI）で組む

画面に並べるのは、デザイナーが気にするもの（トークン・Web ページ・画面・レイヤー）であり、telldes の機能ではない。機能ごとに分けると、同じレイヤーの違反と補足が別々の場所に入り、直す場所と知らせる場所がずれる。

- 違反・知らせ・補足は、ファイル・トークン・画面・レイヤーのどれかの持ち物として出す。持ち主は、デザイナーが下す1つの判断の対象で決める。同じ色が30か所で使われていれば、直す判断は「この色をどのトークンにするか」の1つなので、トークンの一覧の1行になる。トークンと同じ値なら、判断は「このトークンにつなぐ」なので、そのトークンの行だけに出す
- どのトークンとも違う値は、トークンの一覧に「トークンにしていない値」の行として並べ、その値の違反・知らせを持たせる。判断の対象は、まだトークンの無い値そのものだから
- 画面の一覧は、そのまま渡すものの明細になる。渡らないもの（非表示のレイヤー、画面の外の部品など）も並べ、zip を開かなくても何が落ちるか分かるようにする
- 操作は対象に付ける。Export は画面の一覧に、Review・Light / Dark・Setup はファイル全体に効くので上部に置く。Setup だけは機能として置く。対象がこのファイル1つに決まっていて、選ぶものが無いから
- テーマの状態は常に見せる。telldes がファイルの状態を書き換えるので、知らせずに変えない。表示と切り替えは1つの `Light | Dark` にまとめる
- Export 設定も持ち主に付ける。題名は Web ページに、切り替える幅・コンテンツ幅は画面に、ダーク対応と共通ルールはファイルに付ける。1つの事実を1か所にだけ置くため（題名は幅が変わっても同じ）。画面がどの Web ページに入るかは、組をデータから決められないので、画面ごとに選んでもらう
- 違反・知らせの「使っている所」を押すと、Figma でそのレイヤーを選ぶだけで、画面は持ち主の詳細のまま動かない。30か所を順に見て直すあいだ、判断の対象を見失わないため

### 画面でないものは別の Figma のページに置く

Figma のページの直下のフレームはすべて画面として渡すので、部品置き場などは別の Figma のページに置く。そのため、Figma のページの数に上限の無い Drafts で作る前提になる。代償として共同編集はできない。非表示のフレームは、ほかの非表示のレイヤーと同じく渡さない。

### テストは実物から取った入力で、約束に照らして確かめる

- 判断を集めた部分に読み取ったデータを与え、結果を正解と丸ごと比べる。一部だけを見るテストは、見ていないところが崩れても通る
- 入力は、実物の見本ファイルから読み取って作る。手で作った入力は、Figma が実際に返す形と食い違いうる
- 正解は今の出力を写して作らない。`prompt.md` と、見本にわざと入れたものの一覧に照らして作る
- Figma でしかわからないこと（読み取った値、画像の書き出し、付け替えの書き込み、画面）は、テストで真似ずに実機で確かめる
