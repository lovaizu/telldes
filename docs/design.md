# Telldes設計書

[README](../README.md) は、デザイナーがTelldesで何を得て、どう使うかを書いている。この文書は、その姿をどう実現するかを、決めたことと理由で書く。使い方の詳しいところは [ガイド](guide.md) にある。実装とこの文書が食い違ったら、この文書が正しい。

## 変えられない条件

- Figmaの無償版で使い、有料の機能に頼らない

  組織内だけに配るプラグインは有料なのでFigma Communityで配る

- TelldesはLLMを持たない（決めたこと）

  その場で質問を作ることも意図を推し量ることもできない

## Telldesが守ること

1. ファイルにある事実だけを渡し、推し量らない

   推し量りは外れても誰も気づかず、Claude Code（以下CC）のコードがそのまま外れる。CSSで同じに描けないもの（特殊なグラデーション、破線など）も、近い見た目をCCに作らせず、Figmaに描かせた画像で渡す

2. 渡す形は、同じ種類は同じ形、同じ事実は1か所にする

   渡せなかったものは渡せなかったと書き、ファイルで指定されていないことは既定の値で埋めずに出さない。崩れると、CCは読み違え、書いていないことを補って作る

3. デザイナーに覚えてもらう約束はFigmaの仕組みで表せないことだけにする

   約束は増えるほど守られず、守られない約束は出力を黙って壊す

4. 幅違いとテーマ違いはTelldesで決めたサフィックス（名前の末尾）で表す

   フレームと変数に同じ決まりを当てる。無償版ではモードが使えず、「同じものの幅違い・テーマ違い」をFigmaの仕組みで表せない。フレーム名に幅を付けるのはデザイナーがすでにしている付け方で、決まりを1つにすれば覚えることも1つで済む。有料版のモード名も同じサフィックスとして読む

5. テーマはフレームを複製せず、変数のつながりを付け替えて見せる

   複製すると同じWebページが別のWebページとして渡り、ライトの変更がダークに伝わらない

6. デザインの判断はデザイナーに、実装の判断はCCの利用者に聞く

   デザイナーはFigmaを開いている今が一番答えやすく、zipを受け取る人はデザイナーとは限らない。LLMを持たないので、デザイナーに聞くことは前もって洗い出し、決まった入力欄にする。欄に収まらないことは、レイヤーごとのnoteと、すべてのWebページに効くRules for every pageの文章で受ける

7. Reviewは作りながら今のWebページで、Exportは作り終えてから選んだWebページをまとめて行う

   デザイナーはページを1つずつ仕上げ、渡すのは最後にまとめてだから

8. ReviewはCCがデザインどおりに作れなくなるときだけ止める

   作法の押しつけで止めると、デザイナーはReviewを聞き流し、本当に壊れるerrorが埋もれる。指定し忘れだと分かるものは止めずに知らせる（notice）

9. 画面は、機能ごとでなく、トークン・Webページ・フレーム・レイヤーの一覧で組む

   error・notice・note・欄はそれを直す判断の対象（持ち主）の行に付ける。機能ごとに分けると、同じレイヤーのerrorとnoteが別の場所に出て、直す場所と知らせる場所がずれる

## 誰が何をし、何を決めるか

| 役目 | すること | 決めること |
|---|---|---|
| デザイナー | デザインし、サフィックス・欄・noteを入れ、errorを直し、Exportする | デザインの判断すべて |
| Figma側（プラグインのうちFigmaに触る部分） | ファイルを読んでデータにまとめ、言われたとおりに書き込み、Exportのときに画像を描く | 何も決めない |
| 判断（プラグインのうちFigmaに触らない部分） | 読んだデータから、Webページとトークンのまとまり、errorとnotice、zipの中身、Setupで作る差、付け替え先を出す | 何を渡し、何で止めるか |
| 画面 | 一覧と詳細を見せ、操作を受けてFigma側と判断に頼む | 何も決めない |
| CC | zipの指示どおりにページを組む | 何も決めず、実装の判断は利用者に聞く |
| CCの利用者 | CCの問いに答える | 実装の判断（フォントの読み込み方、ファイルの置き場所など） |

判断をFigmaに触らない部分へ集めるのは、そこだけがFigmaなしで動かせ、渡すものが正しいかを確かめられるから。

## 何がどう動くか

操作で切り替わる状態は今のテーマだけ。設定・欄の値・noteはデザイナーが書く中身で、Reviewの結果は読み取るたびに作り直す。

| 操作 | 起きること |
|---|---|
| プラグインを開く | ファイルを読み取る。最初のテーマ以外のまま残っていれば、戻すよう促す |
| Setup | 推奨の一式と今あるものの差だけを作る |
| 設定・欄・noteを入れる | ファイルに保存する |
| Review | キャンバスで選んでいるレイヤーのあるWebページ（または一覧で選んだWebページ）を、読み取り直して判断する |
| テーマの切り替え | 選んだFigmaのページ全体で、変数のつながりをそのテーマのサフィックスの変数に付け替え、今のテーマをファイルに保存する |
| Export | 選んだWebページを読み取り直してReviewし、errorが無ければ、その同じ読み取りからzipを作り、画像を描かせる。テーマがあれば、テーマごとに付け替えて画像を描かせ、終わったら（失敗しても）最初のテーマに戻す |

## 何で判断するか

- 渡す範囲は、設定で選んだFigmaのページの直下にある、表示中のフレーム

  部品置き場や下書きのページと分けられるように、ページはデザイナーが選ぶ

- 幅のサフィックスを除いた名前が同じフレームは1つのWebページになる

  サフィックスの無いフレームはどの幅でも使う1枚のWebページになる

- サフィックスを除いた名前が同じ変数は1つのトークンになる

  幅かテーマのサフィックスはコレクション名・変数名・モード名のどれに持たせてもよい。CSSでは幅かテーマで値が切り替わる。サフィックスの無い変数はどこでも同じ値のトークンになる

- 部品は、すべてのバリアントと一緒に一度だけ渡し、ページは使った部品とバリアントを指す

  同じ部品をページごとに書くと同じ事実が何か所にもなり、使っていない状態（ホバーなど）は渡らないから

- CSSの値になる変数とスタイルはトークンとして、それ以外は値のまま渡す

- 止めるのは見た目が変わるときだけで、指定し忘れは知らせ、変数やAuto Layoutを使わないことには何も言わない

  | 分け方 | 基準 | 例 | Export |
  |---|---|---|---|
  | error | 渡したものからCCが作るページが、ファイルのデザインと違う見た目になる | テーマがあるのに、変数につないでいない色がある。サフィックスの変数に相手が無い。フレームの幅と違う幅の変数を使っている。1つのWebページに同じ幅のフレームが2つある | 止める |
  | notice | 指定し忘れだと機械的に分かるが、渡しても見た目は変わらない | トークンと同じ値なのに、つないでいない。Webページに描いていない幅がある | 止めない |
  | 何も言わない | デザイナーが選んだやり方で、渡しても見た目は変わらない | 変数を使わない。Auto Layoutを使わない（描いた幅では、座標どおりに同じ見た目になる） | 止めない |

- errorとnoticeはデザイナーが下す1つの判断の対象に付ける

  同じ色が30か所で使われていても、判断は「この色をどうするか」の1つなので、1つにまとめて出す

## 何が残り、誰が書き、誰が読むか

| もの | 置き場所 | 書く | 読む |
|---|---|---|---|
| デザイン・変数・スタイル | Figmaのファイル | デザイナー、Setup | Figma側 |
| 設定（読むFigmaのページ、幅とテーマのサフィックス）・欄の値・note | Figmaのファイル（プラグインのデータ） | デザイナーが画面から | 判断 |
| 今のテーマ | Figmaのファイル（プラグインのデータ） | テーマの切り替えとExport | 開いたときの画面 |
| zip | デザイナーの手元 | Export | CCとその利用者 |

zipには次のものが入る。

- CCへの指示（`prompt.md`）
- トークン（`tokens.json`）
- 部品とそのバリアントの記述と画像
- フレームごとの中身の記述（`spec.json`）と画像
- 画像アセット
- 入っているものと渡せなかったもの（`README.md`）

## いつも成り立つこと

- zipは直前のReviewと同じ一度の読み取りから作られている

  別々に読むとReviewでerrorが無かったものと違うものが渡りうる

- Exportの前のReviewはExportが渡すWebページだけを見る

  違うと、渡さないものを直さないとExportできなくなる

- Exportが終わったファイルは失敗したときも含めて最初のテーマになっている

- 渡せなかったものはすべてzipの `README.md` に書かれている

- Setupは何度押しても増えず、手で作ったものを上書きしない

  Setupを使わずに作ったファイルも同じに読める

## 代償と、選ばなかったやり方

| 選んだこと | 代償 | 選ばなかったやり方 | 取らない理由 |
|---|---|---|---|
| 事実だけを渡す | Auto Layoutを使わないフレームは座標のまま渡り、CCは伸び縮みを知りようがない | Auto Layoutを強制する | 描いた幅では見た目は壊れておらず、覚える約束が増える |
| 幅違い・テーマ違いをサフィックスで表す | フレームと変数の名前の末尾をそろえる約束が1つ増える | Sectionで囲む | Sectionをキャンバスの整理に使えなくなる |
| | | 幅違いに同じ名前を付ける | 名前から幅が分からなくなり、変数には使えない |
| | | プラグインの画面で組を選ぶ | 組がファイルに見えず、変数には使えない |
| | | 有料版のモードだけを使う | 無償版で使えない |
| 欄に収まらないことは文章で受ける | 書き方しだいで、CCの読み方がぶれる | すべてを欄にする | 前もって洗い出しきれない |
| | | Figmaの注釈をnoteに使う | 無償版で使えるか確かでない |
| テーマは変数の付け替え | ファイルが今のテーマという状態を持ち、キャンバスでテーマを並べて比べられない（比べるのはExportした画像） | フレームの複製 | 同じWebページが別のWebページとして渡る |

## 仮定

- 無償版では変数のコレクションの数に上限が無い
- 同じファイルの部品は、画面に置いたものから、使っていないバリアントまでプラグインから読める
- 選んだFigmaのページ全体の変数のつながりをプラグインから付け替えられる
