# Telldes 設計書

この設計書は、Telldes を直す人（ユーザーと CC）が、その変更が目的に合うかを判断できるように、README と実装からは読めない意図と決めたこと（理由と代償）を残す。使い方は README に、仕組みはコードに、直した経緯は git にある。

## 目的

Figma で作った LP / HP のデザインを、Claude Code（CC）がカンプと同じ見た目のコードにできるようにする。カンプの画像だけを渡すと、背景と中身の区別、色・大きさ・間隔の値、見出しのレベル、どこが伸びてどこが固定か、動きを CC が推測し、外れる。

出力の正確さを何より優先する。出力が不正確なら、CC のコードもそのまま不正確になる。

## 前提

- デザイナーは1人。作るのは LP / HP
- Figma は無償版で使う。有料の機能には頼らない。組織内だけに配るプラグインは有料なので、Figma Community に公開する
- デザイナーに新しい作法を覚えさせない。Figma 公式のベストプラクティスを土台にし、telldes 独自の約束は公式のやり方で表せないことだけに限る。独自の約束は増えるほど守られない

## 決めたこと

### ファイルにある情報を書き出し、推測しない

ベストプラクティスどおりに作ったファイル（Auto Layout、変数、スタイル、コンポーネント）には、コードに要る情報がそろっている。telldes はそれを書き出すだけで、値から意図を推測しない。推測は外れても誰も気づかない。

Figma のデータに無いことは、デザイナーからプラグインで受ける。それでも無いものは「無い」と書いて渡す。CSS で同じに描けないもの（特殊なグラデーション、破線など）は Figma に描かせた画像で渡し、それもできなければ「含まれなかったもの」として伝える。近い見た目を CC に作らせない。

レスポンシブもこの考えで分ける。出力する Web ページ（HP なら top・about など）の幅ごとの見た目は別のフレームが持つ。どのフレームが同じ Web ページかは Figma の Section で表す（次の節）。どの幅からそのフレームを使うか、コンテンツ幅は、デザイナーがプラグインの入力欄（Export 設定）で宣言する。1440px のフレームの左右 340px の余白が、ただの余白なのかコンテンツ幅を作るものなのかは、描かれた幅では同じ見た目になり、データからは決められないから。

出力の形は次の4つを守る。

- 同じ種類のものは同じ形で出す
- 同じ事実を2か所に書かない
- 落としたものは、落としたと書く
- 指定されていないことは出さない

### Web ページの組は Figma の Section で表す

幅違いのフレームは Figma の Section で囲み、Section 名を Web ページ名（zip のフォルダ名）として読む。1枚だけの Web ページは Section で囲まなくてよく、フレーム名が Web ページ名になる。

Section は Figma 公式の仕組みなので、デザイナーに telldes だけの操作を覚えさせずに済み、組がキャンバスに見える。フレーム名から推し量ると打ち間違いに気づけない。プラグインの設定で選ばせると、組がファイルに見えず、Figma を開いた人に伝わらない。1枚だけの Web ページまで囲ませると、手間が増えるだけで得るものが無い。

代償として、渡す画面を置く Figma のページでは、Section をキャンバスの整理には使えない。Section 名・フレーム名が空か重複すると zip のフォルダがぶつかるので、Review で error にする。

### デザインの判断はデザイナー、実装の判断は CC の利用者に聞く

デザインの判断はプラグインが Figma の上でデザイナーから受け、実装の判断（フォントの読み込み方、置き場所など）は CC が利用者に確認する。デザイナーは Figma を開いている今が一番答えやすく、zip を受け取る人がデザイナーとは限らない。

telldes は LLM を持たず、質問をその場で作れない。そこで、デザインするなら決めないといけないことを前もって洗い出し、決まった入力欄として用意する（Export 設定）。欄にするのは、CC が値としてそのまま使うもの（切り替える幅、コンテンツ幅、ダーク対応の有無、Web ページの題名）だけ。自由に書かせると書き方がぶれて機械的に読めないから。それ以外は文章で受ける。すべての Web ページに効くことは共通ルール（Rules for every page）に、個々のレイヤーのことは note（レイヤーごとの補足の文章）に書く。Figma 標準の注釈は無償版で使えないので、note はプラグインで受ける。

### 判断は Figma に触らない部分に集める

Figma から読む部分は、読んだものを JSON にできるデータにまとめ、言われたとおりに書き込むだけで、判断しない。出力の中身・Review・テーマの付け替えの判断は、そのデータだけを受ける部分に集める。Figma なしで動かせ、テストで確かめられるのはこの部分だけだから。

Review と Export の出力は、一度読んだ同じデータから作る。別々に読むと、Review したものと渡したものがずれうる。

### Review は出力が壊れるときだけ止める

error にするのは、渡しても CC が正しく作れないものだけ。Dark に付け替わらない色（ダーク対応 ON で変数につないでいない色）、zip のフォルダ名がぶつかる Web ページ名がそれにあたる。「変数を使え」は error にしない。Auto Layout 未適用・Figma のデフォルト名・同じ親の中の同名も error にしない。ファイルにあるまま（座標・名前）渡せば、出力は壊れないから。

指定し忘れたと機械的に分かるもの（トークンと同じ値なのにつないでいない、など）は、止めずに知らせる。同じ原因の違反は1行にまとめる（同じ色が30か所なら1行）。

ライトだけのファイルで値が変数になっていないことは、どこにも報告しない。値は `spec.json` に載り、CC は正しく作れる。並べると LP 1枚で数十〜数百行になり、本当に落としたものが埋もれるうえ、「変数を使え」と促すことにもなる。

Review が見るのは、Export が書き出すのと同じ範囲だけ。渡さないものを直さないと渡せない、という状態を作らない。範囲は同じ判定を共有し、Review と zip の対象がずれないようにする。Review はプラグインを開いたとき・設定を変えたとき・Export の実行前に自動で走る。error の件数を常に見せるには、開いた直後から値が要るから。

### ダークモードはフレームを複製せず、変数を付け替える

無償版では1つのコレクションに複数のモードを作れないが、コレクションの数には制限が無い。そこで変数を Light・Dark・Base（テーマで変わらないもの）の3つのコレクションに分け、Figma のページ全体の変数のつながりを Light と Dark の間で付け替える。フレームを複製すると、同じ Web ページが別の Web ページとして CC に渡り、Light の変更が Dark に伝わらない。

代償として、ファイルが「今どちらのテーマか」という状態を持つ。Export の途中で失敗しても必ず Light に戻し、それでも Dark で残った場合は、次に開いたときに戻すよう促す。また、キャンバスで Light と Dark を並べて比べられない。比べるのは Export した画像で行う。

### 変数とスタイルの一式は Setup が作る

無償版ではファイルをまたいで変数を共有できず、手で作らせると、使える欄の絞り込みや CSS 変数名の設定を漏らす。何度押しても増えないように、あるべき一式と今あるものの差だけを作る。Setup を使わずに作ったファイルも、そのまま読めて正しく出る。

### プラグインの画面はオブジェクト指向（OOUI）で組む

画面に並べるのは、デザイナーが気にするもの（トークン・Web ページ・フレーム・レイヤー）であり、telldes の機能ではない。機能ごとに分けると、同じレイヤーの違反と補足が別々の場所に入り、直す場所と知らせる場所がずれる。

- 違反・知らせ・note は、ファイル・トークン・値・フレーム・レイヤーのどれかの持ち物として出す。持ち主は、デザイナーが下す1つの判断の対象で決める。同じ色が30か所で使われていれば、直す判断は「この色をどうするか」の1つなので、トークンの一覧の1行になる。トークンと同じ値なら判断は「このトークンにつなぐ」なので、そのトークンの行に出す。どのトークンとも違う値は「トークンにしていない値」の行として並べる。判断の対象は、まだトークンの無い値そのものだから
- Frames の一覧は、そのまま渡すものの明細にする。渡らないものも並べ、zip を開かなくても何が落ちるか分かるようにする。1枚だけの Web ページはフレームの行として出す。Web ページとフレームが同じ名前で2段に並ぶと、何の区別か分からないから
- 操作は対象に付ける。上部に置くのは、ファイル全体の状態と操作だけ。Light | Dark は、telldes がファイルの状態を書き換えるので知らせずに変えないために常に見せ、表示と切り替えを1つにする。Review は自動で走るので見るべきは件数で、押すのは Figma で直したあとだけ。Export はいつもファイル全体を書き出すので、一覧に置くと一部だけを書き出すように見える。Setup が作るのはトークンなので、トークンの一覧に置く。最初に1回押すだけのものを Export と同じ重さで上部に置かない。そのぶん、足りないトークンがあるときはトークンのタブに印を出し、タブを開かなくても Setup ですることがあると分かるようにする
- Export 設定も持ち主に付け、1つの事実を1か所にだけ置く。題名は幅が変わっても同じなので Web ページに（1枚だけの Web ページでは、そのフレームの詳細で入れる）、切り替える幅・コンテンツ幅はフレームに、ダーク対応と共通ルールはファイルに付ける
- 違反・知らせの「使っている所」を押すと、Figma でそのレイヤーを選ぶだけで、画面は持ち主の詳細のまま動かない。30か所を順に見て直すあいだ、判断の対象を見失わないため
- プラグインの画面の言葉は英語にする。Figma の画面も、Community で使う人も英語だから

### 画面でないものは別の Figma のページに置く

Figma のページの直下の表示中のフレームはすべて画面として渡すので、部品置き場などは別の Figma のページに置く。そのため、Figma のページの数に上限の無い Drafts で作る前提になる。代償として共同編集はできない。非表示のフレームは、ほかの非表示のレイヤーと同じく渡さない。

### テストは実物から取った入力で、約束に照らして確かめる

- 判断を集めた部分に読み取ったデータを与え、結果を正解と丸ごと比べる。一部だけを見るテストは、見ていないところが崩れても通る
- 入力は、実物の見本ファイルから読み取って作る。手で作った入力は、Figma が実際に返す形と食い違いうる
- 正解は今の出力を写して作らない。`prompt.md` と、見本にわざと入れたものの一覧に照らして作る
- Figma でしかわからないこと（読み取った値、画像の書き出し、付け替えの書き込み、画面）は、テストで真似ずに実機で確かめる

## Telldes 独自の約束

デザイナーに覚えてもらう、telldes だけの約束。それぞれ、Figma 公式のやり方では表せない。

| 約束 | 公式のやり方で表せない理由 |
|---|---|
| 変数のコレクション名を Light・Dark・Base にする | 無償版では1つのコレクションに複数のモードを作れない |
| Figma のページ直下の表示中のフレームを、すべて渡す画面として読む | どのフレームを渡すかを示す印が Figma に無い |
| Section を Web ページとして読む | 幅違いのフレームが同じ Web ページだという情報が Figma に無い。Section は組を見せる公式の仕組みなので、その読み方だけを約束にする |
| note をプラグインで書く | 無償版に注釈が無い |
| Export 設定（切り替える幅・コンテンツ幅・ダーク対応・題名・共通ルール）をプラグインで入れる | 描かれたデータに無い |

推奨トークン名は約束ではない。名前は自由で、Setup の一式は共通の語彙にすぎない。
