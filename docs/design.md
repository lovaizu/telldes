# Telldes 設計書

[README](../README.md) は、デザイナーが Telldes で何を得て、どう使うかを書いている。この文書は、その姿をどう実現するかを、決めたことと理由で書く。使い方の詳しいところは [ガイド](guide.md) にある。実装とこの文書が食い違ったら、この文書が正しい。

## 変えられない条件

- Figma の無償版で使う。有料の機能に頼らない。組織内だけに配るプラグインは有料なので、Figma Community で配る
- 作るのは、1人のデザイナーによる LP / HP
- Telldes は LLM を持たないと決めている。その場で質問を作ることも、意図を推し量ることもできない

## Telldes が守ること

- ファイルにある事実だけを渡し、推し量らない。推し量りは外れても誰も気づかず、Claude Code（以下 CC）のコードがそのまま外れる。CSS で同じに描けないもの（特殊なグラデーション、破線など）も、近い見た目を CC に作らせず、Figma に描かせた画像で渡す
- 渡す形は、同じ種類は同じ形、同じ事実は1か所にする。渡せなかったものは渡せなかったと書き、ファイルで指定されていないことは既定の値で埋めずに出さない。崩れると、CC は読み違え、書いていないことを補って作る
- デザイナーに覚えてもらう約束は、Figma の仕組みで表せないことだけにする。約束は増えるほど守られず、守られない約束は出力を黙って壊す
- 幅違いとテーマ違いは、Telldes で決めたサフィックス（名前の末尾）で表し、フレームにも変数にも同じ決まりを当てる。無償版ではモードが使えず、「同じものの幅違い・テーマ違い」を Figma の仕組みで表せない。フレーム名に幅を付けるのはデザイナーがすでにしている付け方で、決まりを1つにすれば覚えることも1つで済む。有料版のモード名も、同じサフィックスとして読む
- テーマはフレームを複製せず、変数のつながりを付け替えて見せる。複製すると同じ Web ページが別の Web ページとして渡り、ライトの変更がダークに伝わらない
- デザインの判断はデザイナーに、実装の判断は CC の利用者に聞く。デザイナーは Figma を開いている今が一番答えやすく、zip を受け取る人はデザイナーとは限らない。LLM を持たないので、デザイナーに聞くことは前もって洗い出し、決まった入力欄にする。欄に収まらないことは、レイヤーごとの note と、すべての Web ページに効く Rules for every page の文章で受ける
- Review は作りながら今の Web ページで、Export は作り終えてから選んだ Web ページをまとめて行う。デザイナーはページを1つずつ仕上げ、渡すのは最後にまとめてだから
- Review は、CC がデザインどおりに作れなくなるときだけ止める。作法の押しつけで止めると、デザイナーは Review を聞き流し、本当に壊れる error が埋もれる。指定し忘れだと分かるものは、止めずに知らせる（notice）
- 画面は、デザイナーが気にするもの（トークン・Web ページ・フレーム・レイヤー）の一覧で組み、error・notice・note・欄は、それを直す判断の対象（持ち主）の行に付ける。機能ごとに分けると、同じレイヤーの error と note が別の場所に出て、直す場所と知らせる場所がずれる

## 誰が何をし、何を決めるか

| 役目 | すること | 決めること |
|---|---|---|
| デザイナー | デザインし、サフィックス・欄・note を入れ、error を直し、Export する | デザインの判断すべて |
| Figma 側（プラグインのうち Figma に触る部分） | ファイルを読んでデータにまとめ、言われたとおりに書き込み、Export のときに画像を描く | 何も決めない |
| 判断（プラグインのうち Figma に触らない部分） | 読んだデータから、Web ページとトークンのまとまり、error と notice、zip の中身、Setup で作る差、付け替え先を出す | 何を渡し、何で止めるか |
| 画面 | 一覧と詳細を見せ、操作を受けて Figma 側と判断に頼む | 何も決めない |
| CC | zip の指示どおりにページを組む | 何も決めず、実装の判断は利用者に聞く |
| CC の利用者 | CC の問いに答える | 実装の判断（フォントの読み込み方、ファイルの置き場所など） |

判断を Figma に触らない部分に集めるのは、そこだけが Figma なしで動かせ、渡すものが正しいかを確かめられるから。

## 何がどう動くか

操作で切り替わる状態は、今のテーマだけ。設定・欄の値・note はデザイナーが書く中身で、Review の結果は読み取るたびに作り直す。

| 操作 | 起きること |
|---|---|
| プラグインを開く | ファイルを読み取る。最初のテーマ以外のまま残っていれば、戻すよう促す |
| Setup | 推奨の一式と今あるものの差だけを作る |
| 設定・欄・note を入れる | ファイルに保存する |
| Review | キャンバスで選んでいるレイヤーのある Web ページ（または一覧で選んだ Web ページ）を、読み取り直して判断する |
| テーマの切り替え | 選んだ Figma のページ全体で、変数のつながりをそのテーマのサフィックスの変数に付け替え、今のテーマをファイルに保存する |
| Export | 選んだ Web ページを読み取り直して Review し、error が無ければ、その同じ読み取りから zip を作り、画像を描かせる。テーマがあれば、テーマごとに付け替えて画像を描かせ、終わったら（失敗しても）最初のテーマに戻す |

## 何で判断するか

- 渡す範囲: 設定で選んだ Figma のページの直下にある、表示中のフレーム。部品置き場や下書きのページと分けられるように、ページはデザイナーが選ぶ
- Web ページのまとまり: 幅のサフィックスを除いた名前が同じフレームが、1つの Web ページになる。サフィックスの無いフレームは、どの幅でも使う1枚の Web ページになる
- トークンのまとまり: 幅かテーマのサフィックスを、コレクション名・変数名・モード名のどれかに持つ変数は、サフィックスを除いた名前が同じもの同士で1つのトークンになり、CSS では幅かテーマで値が切り替わる。サフィックスの無い変数は、どこでも同じ値のトークンになる
- トークンか値か: CSS の値になる変数とスタイルはトークンとして渡し、それ以外は使った所に値のまま渡す
- 止めるか、知らせるか、何も言わないか

  | 分け方 | 基準 | 例 | Export |
  |---|---|---|---|
  | error | 渡したものから CC が作るページが、ファイルのデザインと違う見た目になる | テーマがあるのに、変数につないでいない色がある。サフィックスの変数に相手が無い。フレームの幅と違う幅の変数を使っている。1つの Web ページに同じ幅のフレームが2つある | 止める |
  | notice | 指定し忘れだと機械的に分かるが、渡しても見た目は変わらない | トークンと同じ値なのに、つないでいない。Web ページに描いていない幅がある | 止めない |
  | 何も言わない | デザイナーが選んだやり方で、渡しても見た目は変わらない | 変数を使わない。Auto Layout を使わない（描いた幅では、座標どおりに同じ見た目になる） | 止めない |

- 持ち主: error と notice は、デザイナーが下す1つの判断の対象に付ける。同じ色が30か所で使われていても、判断は「この色をどうするか」の1つなので、1つにまとめて出す

## 何が残り、誰が書き、誰が読むか

| もの | 置き場所 | 書く | 読む |
|---|---|---|---|
| デザイン・変数・スタイル | Figma のファイル | デザイナー、Setup | Figma 側 |
| 設定（読む Figma のページ、幅とテーマのサフィックス）・欄の値・note | Figma のファイル（プラグインのデータ） | デザイナーが画面から | 判断 |
| 今のテーマ | Figma のファイル（プラグインのデータ） | テーマの切り替えと Export | 開いたときの画面 |
| zip | デザイナーの手元 | Export | CC とその利用者 |

zip には、CC への指示（`prompt.md`）、トークン（`tokens.json`）、フレームごとの中身の記述（`spec.json`）と画像、画像アセット、入っているものと渡せなかったもの（`README.md`）が入る。

## いつも成り立つこと

- zip は、直前の Review と同じ一度の読み取りから作られている。別々に読むと、Review で error が無かったものと違うものが渡りうる
- Export の前の Review は、Export が渡す Web ページだけを見る。違うと、渡さないものを直さないと Export できなくなる
- Export が終わったファイルは、失敗したときも含めて最初のテーマになっている
- 渡せなかったものは、すべて zip の `README.md` に書かれている
- Setup は何度押しても増えず、手で作ったものを上書きしない。Setup を使わずに作ったファイルも、同じに読める

## 代償と、選ばなかったやり方

| 選んだこと | 代償 | 選ばなかったやり方 | 取らない理由 |
|---|---|---|---|
| 事実だけを渡す | Auto Layout を使わないフレームは座標のまま渡り、CC は伸び縮みを知りようがない | Auto Layout を強制する | 描いた幅では見た目は壊れておらず、覚える約束が増える |
| 幅違い・テーマ違いをサフィックスで表す | フレームと変数の名前の末尾をそろえる約束が1つ増える | Section で囲む | Section をキャンバスの整理に使えなくなる |
| | | 幅違いに同じ名前を付ける | 名前から幅が分からなくなり、変数には使えない |
| | | プラグインの画面で組を選ぶ | 組がファイルに見えず、変数には使えない |
| | | 有料版のモードだけを使う | 無償版で使えない |
| 欄に収まらないことは文章で受ける | 書き方しだいで、CC の読み方がぶれる | すべてを欄にする | 前もって洗い出しきれない |
| | | Figma の注釈を note に使う | 無償版で使えるか確かでない |
| テーマは変数の付け替え | ファイルが今のテーマという状態を持ち、キャンバスでテーマを並べて比べられない（比べるのは Export した画像） | フレームの複製 | 同じ Web ページが別の Web ページとして渡る |

## 仮定

- 無償版で、変数のコレクションの数に上限が無い
- 選んだ Figma のページ全体の変数のつながりを、プラグインから付け替えられる
