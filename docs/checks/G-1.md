## QA是正メモ（Self-check）

独立QAレビューで指摘された3件の曖昧性は、いずれも `docs/telldes-design.md` の 4.5.1 / 4.5.2.1 への追記で解消済み（対象箇所は本コミットの2スポットのみ、他セクション・コード未変更）。

1. **letterSpacing=0 / sparse-vs-full の矛盾**: 4.5.1 に追記した段落で明記。引用: 「`$value` は Text Style の canonical な定義値であり、個々のノードに対する解決済みメトリクスではない。そのため 4.5.2.1 の `text.*` フィールドで採用している「既定値は省略」という間引き規約はここには適用されず、各値が既定的かどうかに関わらず `fontFamily` / `fontSize` / `fontWeight` / `lineHeight` / `letterSpacing` の 5 キーを常にすべて含める（例の `"letterSpacing": "0em"` はこの規約により省略しない）。」
2. **lineHeight AUTO の解決方針**: 同段落内で明記。引用: 「`lineHeight` が Text Style 上 AUTO 設定の場合も同様に省略や `"AUTO"` という文字列での出力はせず、そのフォントサイズにおける計算後の line-height をpx値に解決して出力する（例 `"33.6px"`）。これは mixed 値を先頭文字の値で解決する他フィールドの方針と同じく、`$value` が常に具体的な解決値を持つようにするためである。」
3. **typographyToken と fontSizeToken/fillToken の関係**: 4.5.2.1 の `typographyToken` 箇条書きの直後に1文追記。引用: 「`typographyToken` と `fontSizeToken` / `fillToken` などのプロパティ単位のトークンは独立しており、併存しうる。`typographyToken` は適用された Text Style を表し、`fontSizeToken` / `fillToken` は個々のプロパティに直接バインドされた Variable を表すため、両者は排他的ではない。同一ノードがどちらか一方のみ、両方、またはいずれも持たない場合があり、各フィールドは加算的（additive）に付与される。」

## Post-approval correction (2026-07-02)

QA是正メモの2.（lineHeight AUTO の解決方針）に記載していた「計算後の line-height をpx値に解決して出力する（例 `"33.6px"`）」は、事後調査の結果、**事実誤り**と判明した。Figma Plugin API（`TextNode.lineHeight` / `getRangeLineHeight`、および `TextStyle` オブジェクトにも同等の getter は存在しない）は AUTO 設定に対して常に `{ unit: "AUTO" }` のみを返し、計算後のpx値は一切公開しない。計算済み `lineHeightPx` はFigmaの別API面（REST/Files HTTP API のレスポンス）にのみ存在する値であり、本プラグインが用いる同期的な Plugin API（`src/code.ts` の `figma.variables.getLocalVariables()` 等）とは無関係のAPIである。本プラグインの設計にネットワーク/認証は含まれないため、この値を取得する手段がなく、「計算後px値への解決」は実装不可能な記述だった。

是正として、`docs/telldes-design.md` 4.5.1 の該当文を「AUTO の場合は CSS の `line-height: normal` に相当するキーワード文字列 `"normal"` を出力する」に置き換えた。是正後の文言（引用）:

> `lineHeight` が Text Style 上 AUTO 設定の場合も同様に省略や `"AUTO"` という文字列での出力はせず、CSS の `line-height: normal` に相当するキーワード文字列 `"normal"` を `$value.lineHeight` に出力する（Figma Plugin API は AUTO 設定の描画後 line-height をpx値として提供しないため、CSS 側の意味的な等価表現を用いる）。これは mixed 値を先頭文字の値で解決する他フィールドの方針と同じく、`$value` が常に具体的な解決値を持つようにするためである。

`"normal"` は常に存在する具体的な文字列値であり、同段落の「composite `$value` は常に5キーをすべて含む（省略しない）」という規約を引き続き満たす。修正範囲は 4.5.1 の当該1段落のみで、同セクションの `heading-md` JSON 例（`"lineHeight": "36px"`、明示的な PIXELS 値）は AUTO と無関係のため変更していない。
